# Отчет о проведенном тестировании мобильного приложения "Мобильный хоспис"

### Тест-кейсы
- Всего создано 107 тест-кейсов, охватывающих все ключевые возможности приложения.

### Автоматизация тест-кейсов
- Из общего числа тест-кейсов был автоматизирован 61 для ускорения процесса проверки функциональности и сокращения трудозатрат ФТ при регрессионном тестировании.
- 60 из 61 автотеста прошли успешно, на основании одного упавшего теста был составлен [баг-репорт](https://github.com/snezhka003/qamid120-diplom/issues/1).
- К проекту подключен инструмент Allure для генерации наглядных отчетов о тестировании. Отчеты по уже пройденным автотестам доступны для просмотра по [ссылке](https://github.com/snezhka003/qamid120-diplom/allure-reults).
- Всего составлено 4 баг-репорта.

### Выявленные баги
1. [Неактивна кнопка выбора раздела About в дропдауне бургер-меню при раскрытии его из раздела News](https://github.com/snezhka003/qamid120-diplom/issues/1) - не блокирующий, но довольно критичный для пользователя.
2. [Записывается неверная дата при сохранении созданной новости](https://github.com/snezhka003/qamid120-diplom/issues/2) - некритичный для пользователя.
3. [Сбрасываются введенные данные при смене ориентации экрана на странице авторизации](https://github.com/snezhka003/qamid120-diplom/issues/3) - не блокирующий, но критичный для пользователя.
4. [Плохое отображение некоторых элементов интерфейса при включении темной темы на устройстве](https://github.com/snezhka003/qamid120-diplom/issues/4) - не блокирующий, но довольно критичный для пользователя.

### Сравнения времени тестирования приложения по чек-листу руками и с помощью UI-тестов
- На ручное тестирование по чек листу затрачено 2,5 - 3 часа.
- Выполнение UI-тестов выполнено за 8 мин 6 сек 263 мсек

### Заключение
Ручное тестирование помогло выявить уникальные баги в кейсах, которые автоматизировать либо сложно, либо нецелесообразно ввиду часто меняющейся логики/реализации или нестабильности поведения системы.
Автоматизация ряда ключевых тест-кейсов, которые не подвержены частым изменениям и нестабильности поведения системы, помогает сократить время общего тестирования системы и высвободить ресурсы ФТ на более приоритетные задачи.

### Рекомендации
Для повышения качества тестирования и сокращения времени на его выполнение необходимо проработать оптимизацию работы системы, приведение ее к максимально стабильному поведению, что в дальнейшем поспособствует расширению автотестов, а также внедрению CI/CD процессов, что в свою очередь позволит обеспечить более быстрое и качественное тестирование приложения.
